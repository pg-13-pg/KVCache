## CMake/CTest 测试入口

仓库中的正式测试由 CMake 注册，不需要逐个手工编译测试源文件：

```bash
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build cmake-build-debug -j6
ctest --test-dir cmake-build-debug --output-on-failure
```

只运行真实三节点进程测试：

```bash
ctest --test-dir cmake-build-debug -L raft_integration --output-on-failure
```

连续运行十轮，用于检查选举和恢复场景是否存在偶发失败：

```bash
ctest --test-dir cmake-build-debug -L raft_integration --repeat until-fail:10 --output-on-failure
```

`raft_integration` 标签当前覆盖 leader 故障转移、整集群重启、快照重启、InstallSnapshot 追赶、WAL 不完整尾部恢复和完整记录校验和损坏。每个测试都有 120 秒 CTest 上限，leader 选举断言固定为 10 秒。

`persister_wal` 组件测试还覆盖二进制状态/快照、递增序号、目录隔离和状态写入自动压缩；压缩后重新打开文件，必须同时恢复最后的 Raft 状态与压缩前已安装的快照。

成功运行会删除临时测试目录。失败时，测试会在 stderr 打印 `cmake-build-debug/test/artifacts/<scenario>-<timestamp>-<pid>` 的绝对路径并保留现场，其中包括：

- `cluster.conf`：本次动态分配的三节点地址。
- `node-N.log`：每个节点的 stdout/stderr。
- `commands.log`：每次 `kvctl` 命令、耗时、退出码、stdout 和 stderr，也包含状态采样。
- `node-N/raft.wal`：节点失败时的持久化状态。

排查完成前不要覆盖这些目录；下一次成功测试不会删除之前保留的失败现场。
